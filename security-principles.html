Security Controls (C, I, A = prinsip yang dilindungi)

✎ Catat di LKPD bagian F: pilih 1 sampai 2 upaya, alasannya, dan keterbatasannya.
Sebelum
Siapa pun bisa login tanpa verifikasi identitas.
Sesudah
Pengguna harus membuktikan identitas lebih dulu.

Authentication melindungi: Confidentiality Mengurangi kemungkinan: Akses Tidak SahPenyalahgunaan Kredensial Kontrol ini tidak menyelesaikan semua masalah.

Sebelum
Semua akun dapat membaca dan mengubah.
Sesudah
Hak baca dan ubah dibedakan sesuai peran.

Access Control melindungi: ConfidentialityIntegrity Mengurangi kemungkinan: Kebocoran InformasiPerubahan Data Tanpa Izin Kontrol ini tidak menyelesaikan semua masalah.

Sebelum
Sandi pendek atau mudah ditebak, dipakai bersama sehingga akun sulit dibedakan.
Sesudah
Sandi panjang dan unik, tidak dibagikan, tiap akun punya kredensial sendiri.

Strong Password melindungi: Mengurangi kemungkinan: Penyalahgunaan Kredensial Kontrol ini tidak menyelesaikan semua masalah.

Sebelum
Port kabel terbuka untuk perangkat apa pun.
Sesudah
Ruang dikunci; port tak terpakai dinonaktifkan.

Physical Security melindungi: Availability Mengurangi kemungkinan: Akses Tidak Sah Kontrol ini tidak menyelesaikan semua masalah.

Sebelum
Data yang tertangkap terbaca jelas.
Sesudah
Data tertangkap tetap tak terbaca tanpa kunci.

Encryption melindungi: Confidentiality Mengurangi kemungkinan: Penyadapan Lalu Lintas Kontrol ini tidak menyelesaikan semua masalah.

1. Perangkat lunak belum diperbarui
2. Kerentanan belum diperbaiki
3. Pembaruan diterapkan
4. Versi baru terpasang

Software Updates membantu memperbaiki kerentanan yang diketahui, tetapi tidak menghilangkan seluruh risiko. Melindungi: IntegrityAvailability

Tidak ada satu kontrol yang menyelesaikan semua masalah; kontrol saling melengkapi.
